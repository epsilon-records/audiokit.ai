Quickstart

Measure a file's loudness

Give AudioKit a signed URL to the file and the file's sha256. You get 202 Accepted straight away and a signed webhook when the job finishes.

shell
curl https://api.audiokit.ai/v1/jobs \
  -H "Authorization: Bearer $AUDIOKIT_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "job_id": "master-0193",
    "operation": "loudness",
    "input": { "url": "https://…/master.wav", "sha256": "837d2e9c…", "filename": "master.wav" },
    "webhook": { "url": "https://you.example/audiokit/webhook" }
  }'
result, in the job.succeeded event
"result": {
  "integrated_lufs": -22.02,
  "loudness_range_lu": 0.0,
  "true_peak_dbtp": -21.33,
  "sample_peak_dbfs": -21.33,
  "sample_rate": 44100,
  "channels": 2,
  "duration_seconds": 5.0
}

Hash the exact bytes your URL serves, for example sha256sum master.wav. A different file, or a transfer that changes it, fails with input_hash_mismatch before any processing.

Authentication

Send your API key as Authorization: Bearer ak_… on every job request. AudioKit stores only a hash of each key. /v1/health and /v1/capabilities need no key. Each client sees only its own jobs: another client's job ID returns 404.

Job request

POST /v1/jobs takes this JSON body. Unknown fields are rejected with 422 invalid_request.

FieldRequiredMeaning
job_idyesYour own ID, 1–200 printable ASCII characters, no spaces. Also the idempotency key.
operationyesprobe or loudness
input.urlyesSigned GET URL. Must be https and resolve to a public address, including after redirects.
input.sha256yes64 hex characters
input.filenamenoOriginal filename, used only as a format hint
paramsnoOperation settings, an object. None are defined yet.
webhook.urlnoWhere to POST the result. Same URL rules as input.url.
authorizationno{ "decision_id", "purpose" }, a reference to your own rights decision. Stored with the job for provenance; AudioKit never needs the underlying documents.

Job object

Returned by submit, status and cancel, and sent as data in webhook events.

{
  "provider_job_id": "01a19981-fb9f-774e-b139-7cc6ac648659",
  "job_id": "master-0193",
  "operation": "loudness",
  "status": "succeeded",
  "result": { "integrated_lufs": -22.02, "…": "…" },
  "provenance": {
    "input_sha256": "837d2e9cc6a5ef10…",
    "audiokit_version": "0.1.0",
    "operation": "loudness",
    "params": {}
  },
  "created_at": "2026-11-01T23:46:35.039517Z",
  "started_at": "2026-11-01T23:46:35.044170Z",
  "finished_at": "2026-11-01T23:46:35.730192Z"
}

status is queued, running, succeeded, failed or canceled. A failed job has error: { "code", "message" } in place of result.

Idempotency

Submitting the same body with the same job_id again returns the existing job with 200 OK, so retries after a timeout are safe. A different body with a job_id you've already used returns 409 idempotency_conflict. To run the same file again, use a new job_id.

Cancellation

POST /v1/jobs/{provider_job_id}/cancel cancels a queued job at once (200) and sends a job.canceled event. A running job stops at its next checkpoint (202). A finished job is returned unchanged (200).

Operations

probe

Decodes the whole file. Returns container, codec, sample_rate, channels, bits_per_sample, frames, duration_seconds, size_bytes, decode_errors and valid (true when every packet decoded).

loudness

EBU R128. Returns integrated_lufs, loudness_range_lu, true_peak_dbtp, sample_peak_dbfs, sample_rate, channels and duration_seconds. Values are rounded to two decimals; silence gives null.

Readable formats: WAV, AIFF, FLAC, MP3, AAC and ALAC in MP4, Ogg Vorbis, CAF and MKV/WebM audio.

Webhooks

When a job finishes, AudioKit POSTs { "event_id", "type", "created_at", "data" } to the job's webhook URL. type is job.succeeded, job.failed or job.canceled; data is the job object. Drop any event_id you've already handled.

Any 2xx response counts as delivered. Otherwise AudioKit retries after 10 s, 1 min, 5 min, 30 min, 2 h and 6 h, then gives up. GET /v1/jobs/{id} always has the final state.

Every event carries X-Signature: t=<unix seconds>,v1=<hex>: an HMAC-SHA256 of "{t}.{raw_body}" with your webhook secret. Reject signatures more than 300 seconds old, and verify against the raw body before parsing it.

verify · node
import crypto from "node:crypto";

export function verify(secret, rawBody, header) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const t = Number(parts.t);
  if (!t || Math.abs(Date.now() / 1000 - t) > 300) return false;
  const mac = crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex");
  return mac.length === parts.v1?.length &&
    crypto.timingSafeEqual(Buffer.from(mac), Buffer.from(parts.v1));
}
verify · python
import hashlib, hmac, time

def verify(secret: bytes, raw_body: bytes, header: str) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(",") if "=" in p)
    t = int(parts.get("t", 0))
    if abs(time.time() - t) > 300:
        return False
    mac = hmac.new(secret, f"{t}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(mac, parts.get("v1", ""))

Job errors

A failed job's error.code is one of these.

input_url_rejectedThe URL isn't https or points at a non-public address
input_unreachableThe download failed or returned a non-2xx status
input_too_largeThe file is over the size limit
input_hash_mismatchThe downloaded bytes don't match input.sha256
unsupported_formatNot a readable audio file, or no audio track
unsupported_codecThe audio track's codec can't be decoded
corrupt_inputDecoding failed partway through
internalAudioKit's fault. Safe to resubmit with a new job_id
